# Popcorn

Personal media library + video player. .NET 10 backend (`Popcorn.Server`), React web UI (`Popcorn.Web`), native MPV-based players for Linux and Windows. Primary dev platform is Linux (Arch); Windows support lags behind.

## Products (what actually ships)

Everything is built around `Popcorn.Server`:

| Variant | Entry project | What it is |
|---|---|---|
| Server + browser UI | `Popcorn.Server` | ASP.NET Core host. Serves `Popcorn.Web` bundle from `web/`, WebSocket RPC at `/ws`, REST video streaming at `api/video`. Runs headless / as systemd user service. Browser playback uses the web player in `Popcorn.Web/src/player`. |
| Linux desktop app | `Popcorn.Linux` | **Rust + CEF** (not .NET, not in `Popcorn.sln`). Single CEF Views window showing `{server}/index.html`. Finds the server via `POPCORN_SERVER_URL` or `localhost:$POPCORN_PORT`; if unreachable runs `systemctl --user start popcorn.service` (starts it again if the unit goes inactive while waiting, e.g. launched during a previous server's shutdown; falls back to spawning `Popcorn.Server` from its own dir with `popcorn.env` if the unit is missing or crash-looping) and shows a waiting page until it answers. Never hosts the server in-process. Adds `PopcornDesktop/<ver>` to the User-Agent → web UI `isDesktopApp` (`Popcorn.Web/src/utils/platform.ts`) hides Float/Dock and sends `FileOpen` (server → native player / default app) instead of using the web player. `-service` is accepted and ignored (old desktop files). |
| Linux player | `Popcorn.Player.Linux` + `Popcorn.Player.Native` | **Wayland only.** .NET executable (player logic: DB, navigation, mpv control via `LibMpvClient`, overlay WebSocket bridge, server socket) that P/Invokes `libpopcorn_player.so` (Rust): raw Wayland window (smithay-client-toolkit); mpv core rendering into a video subsurface placed *below* the main surface — with a libmpv that has the DMA-BUF render API (`render_dmabuf.h`, our mpv patch) mpv renders with its own Vulkan device into GBM buffers we attach as linux-dmabuf `wl_buffer`s, otherwise libmpv OpenGL render API on EGL; CEF off-screen overlay (the shared player UI from `Popcorn.Web`, `player.html` entry, served as `http://app.local/index-chrome.html` from `web-player/`) on the main surface — CEF's shared-texture DMA-BUFs copied on the GPU (EGL/GLES blit) into our own dmabuf buffers, or wl_shm from software paint as fallback; input is forwarded to CEF. Works standalone without the server. Launched by server via `LinuxPlayerService`. |
| Windows desktop app | `Popcorn.Windows` (+ `Popcorn.Windows.Tray` in the server) | WinForms + **WebView2** counterpart of `Popcorn.Linux` (no CEF on Windows: WebView2 is preinstalled and shared). One window on `{server}/index.html` (`POPCORN_SERVER_URL` or `localhost:$POPCORN_PORT`); if unreachable starts `Popcorn.Server.exe` from its own folder and shows the waiting page (`wait.html`, copy of Popcorn.Linux's). `PopcornDesktop/<ver>` UA, popups → default browser, F11 / HTML5 fullscreen, single instance per user (mutex + named pipe; a second launch's `--open-path` is handed over). No Windows service: the server is a plain background process (`WinExe` in Windows Release builds, `Local\Popcorn.Server` mutex = single instance, autostart via HKCU Run key from the installer / `install_windows.ps1`, switched on and off like Task Manager → Startup apps does (`StartupApprovedRun` state) by `INativeAutostart` (`Popcorn.Shared/Windows/WindowsAutostart.cs`, `Popcorn.Shared/Linux/LinuxAutostart.cs` = `systemctl --user enable/disable popcorn.service`, supported when the unit file exists; `UnsupportedAutostart` elsewhere; Settings page General → Startup, sockets `Autostart`/`AutostartSet`; never stored in Popcorn's settings). Task Manager shows the server's AssemblyTitle/Company "Popcorn") with a notification-area icon (`Popcorn.Windows.Tray`, raw Win32 so the server stays plain `net10.0`; left click / Open app → `Popcorn.Windows.exe`, Open in browser, Exit). |
| Windows player | `Popcorn.Player.Windows` + `Popcorn.Player.Windows.Native` | Same split as the Linux player: .NET executable (same player logic, `LibMpvClient`, overlay WebSocket bridge, named-pipe server link) that P/Invokes `popcorn_player.dll` (Rust): Win32 main window (native frame) with mpv's own video output inside it (`wid`, mpv's D3D11 swapchain), and the overlay as a separate borderless window **owned** by it and kept over its client area: WebView2 (windowed hosting, transparent background, `WS_EX_NOREDIRECTIONBITMAP`) on `http://app.local/index-chrome.html` (virtual host → `web-player/`). Two top-level windows on purpose: DWM draws mpv's swapchain over anything else inside the same top-level window (child windows, DirectComposition visuals — the old WPF player's UI vanished as soon as video played), an owned window is always composed above its owner. The overlay is activated in place of the main window (which keeps painting its caption active); F11 fullscreen. Launched by server via `WindowsPlayerService` from `<server dir>\Player\Popcorn.Player.Windows.exe`; also `Popcorn.Player.Windows.exe <file|fileId>`, no argument = "drop a file" screen. |

The old Windows Blazor/WebView app (`Popcorn/`, `Popcorn.WebView`, and its old .NET `Popcorn.Installer`) was removed — do not reintroduce references to it. Today's `Popcorn.Installer` is the unrelated Rust installer/updater below.

## Communication

1. **Web UI ↔ Server** — WebSocket `/ws`, custom RPC.
   - Text frames: JSON `{ type, payload }`, camelCase. Binary frames: UTF-8 prefix `"type,param1,param2;"` followed by bytes (images/thumbnails).
   - Server handlers: classes marked `[WebSocketService]`, methods marked `[WebSocketEvent(SocketRequests.X)]` / `[WebSocketBinaryEvent]`, discovered by reflection in `WebSocketServices.RegisterWebServices`. Handlers are resolved per-message from a DI scope.
   - Event names: `Popcorn.Server/Models/SocketRequests.cs` must stay in sync with `Popcorn.Web/src/socket/socket-requests.ts`.
   - Client: `Popcorn.Web/src/socket/websocket-client.ts` (auto-reconnect, send queue), hooks `useSocketEvents` / `useSocketBlobEvents`.
2. **Web UI ↔ Server (HTTP)** — `VideoController` (`api/video/{fileId}`, `/metadata`, `/audio/{trackId}`, `/subtitles/{trackId}`) for in-browser playback (a file still downloading redirects to the `DownloadsController` stream; separate audio/subtitle extraction answers 409 until it is complete). `DownloadsController`: `api/downloads/{id}/files/{index}` (waiting range stream), `api/downloads/playback?path=` / `playback/{fileId}` (download state + downloaded ranges as fractions of playback time via the container index, `MediaTimeline`: MKV/WebM Cues, MP4 sample tables, byte fractions when there is none; used by both players: seek bar `Components/ProgressBar/SeekBar.tsx`, the Linux player plays the stream URL with mpv `network-timeout=0` instead of the incomplete file).
3. **Server ↔ native player** — Linux: unix socket `/tmp/popcorn_bridge.sock` (`PlayerBridgeServer`, JSON events like `LoadMediaEvent`). Windows: named pipes, see `Docs/Video player connection.md`.
4. **Player app ↔ its overlay UI** — `Popcorn.Player.Core/Web/` (`IWebBridge` = `SocketWebBridge`): Fleck WebSocket on 127.0.0.1, address injected into the overlay page (`window.wsAddress`) by the native layer (Linux: CEF scheme handler, Windows: WebView2 `AddScriptToExecuteOnDocumentCreated`).
5. **Plugins** — search is entirely plugin-provided, see `Docs/Plugins.md`. Image providers `IImageProvider` (`ImageKinds` = Poster and/or Backdrop) feed the pictures of library items: `PluginWebService.ImageSearch` (`MediaImageSearch`, name parsed with `MediaNameParser`, all providers of the kind in parallel) → `components/image-picker/media-image-picker.tsx` (Add to Library modal, item page Edit pictures); the pick (provider http(s) URL or uploaded file as data: URL) goes in `CreateMediaItem` (JSON) / `SetMediaItemImage` and is stored by `MediaImageService` (Application) in `<data>/images` as `MediaItem.ImagePath` (poster) / `BackdropPath` (unique file name per save, old file deleted, also on item removal). New library items get `MediaItem.Description` in `MediaItemService.CreateMediaItemFromScan` via `IMediaDescriptionProvider` (`PluginHost/PluginMediaDescriptions`: `MediaDetails.Overview` of the best search match of the first media source plugin in the user's order that has one, 10 s limit). Two search kinds (a plugin class may implement both): media sources `IMediaSourcePlugin` (what exists: search + details; Search page Media tab) and file sources `IFileSourcePlugin`, or several per plugin via `IFileSourceProvider` → `FileSource`s (each its own provider in the UI, web key `pluginId/sourceId`, `""` = the plugin itself) (where to get it: returns `FileResult`s with typed `FileLink`s — Magnet/Torrent/Direct/Page; `FileLink.Resolve` = fetched only when used: the file source's `IFileLinkResolver`, socket `PluginResolveLinks` (off the socket loop, 30 s), called by `useOpenLink` / `useDownloadFiles` before acting; Search page Files tab + Files section under media details, queried with `MediaDetails.FileQuery` = title/year/IMDb id). Popcorn only handles links generically (`src/plugins/file-sources.ts` `useOpenLink(link, target, media)`: the link kind picks the action (Magnet/Torrent = torrent, Direct = direct download); target `internal` → `DownloadAdd` (built-in downloader, added to the library with the details page's title/poster), `external` → browser: magnet to OS / new tab, desktop app: server `OpenLink` → `FileService.OpenUrl` = xdg-open; default target per kind from settings (`useInternalTorrentClient`, `downloads.useInternalDirectDownloader`)); never integrate a specific site into the app. `PluginManager` (`Popcorn.Server/PluginHost`) loads `plugins/<id>/plugin.json` + assembly (own `AssemblyLoadContext`; `Popcorn.Plugins.Abstractions` + `Microsoft.Extensions.*` always from the server) from `<data>/plugins` then `<server dir>/plugins` (collectible contexts; rescanned on every change; plugins without a search role implement `IServicePlugin`; every loaded plugin is disposed at server shutdown, `UnloadAll` on `ApplicationStopping`, so plugins may own processes); `PluginWebService` serves `PluginList` (all folders in the user's order, incl. disabled/broken; `media` flag, `fileSources` with per-source name/icon/sort fields, `iconUrl` from manifest `icon`)/`PluginSearch`/`PluginDetails`/`PluginFileSearch` (`pluginId` + `sourceId`, client `requestId` echoed)/`OpenLink`/`PluginSetEnabled`/`PluginSetOrder`/`PluginUninstall`, `PluginsController` (`POST api/plugins`, zip) installs into `<data>/plugins/<id>`; disabled ids + order in `<data>/plugins/plugins.json`; managed from Settings → Plugins (`pages/settings/plugin-list.tsx`); plugin settings: fields declared in plugin.json `settings` (`PluginSettingField`: text/password/number (whole)/float/boolean/select, `list` for text/password/number/float, optional `group` heading), form `pages/settings/plugin-settings-dialog.tsx`, sockets `PluginSettings`/`PluginSettingsSave`, stored by `PluginSettingsFile` in `settings.json` in the plugin folder (bundled plugins: `<data>/plugins/<id>/`, their folder is replaced on install; zip updates keep it), passwords never sent to the browser; plugins read it via `IPluginSettings` (constructor), saving reloads the plugin; buttons in the settings dialog: `IPluginActions` on the plugin class (`PluginAction` list + `RunActionAsync`; sockets `PluginSettings` (`actions`) / `PluginAction`, run off the socket loop, 2 min limit; a plugin with actions gets the dialog without fields); plugins share string values by name through `IPluginVariables` (constructor; `PluginHost/PluginVariables.cs`: `PluginVariableStore` singleton = mediator, in memory, a value belongs to the plugin instance that set it last and is dropped when it unloads); status messages through `IPluginStatus` (constructor; `PluginHost/PluginStatus.cs`, per instance, keyed, cleared on unload; `PluginInfo.status`, shown by `pages/settings/plugin-status.tsx` on the plugin row and in the settings dialog; changes raise `PluginManager.StatusChanged`, on which every open socket gets `PluginList` (`Startup.HandleWebSocket`, 200 ms coalescing)); plugin `web/` is served at `/plugins/<id>/` (`PluginWebFileProvider`, follows the loaded set). Web: `src/plugins/` — file sources are searched lazily (Files tab opened / details page button; `useFileSearch` in `file-sources.ts`, state owned by the caller), shown by `file-results.tsx` (combined list by default or per provider, sorted by plugin `SortFields`/`FileResult.SortValues`, refresh per provider; view prefs in localStorage); result groups `provider-group.tsx` (collapsed state persisted in localStorage, first 10 + Show all); slots `PluginSearchCard`/`PluginDetails`/`PluginDetailsCard`/`PluginFileCard` render the plugin's UI module export (dynamic `import()`) or the built-in component (`default-components.tsx`). Plugin UI modules share react/react-dom/@mantine via an import map that `vite.config.ts` (`pluginSharedModules`) generates; the list is `plugin-sdk/shared.js` — changing it or the contract is an API change (`PluginApi.Version`).
6. **Linux player .NET ↔ native** — C ABI in `Popcorn.Player.Native/src/lib.rs` (`pn_init`, `pn_mpv_core`, `pn_run`, `pn_quit`, `pn_set_fullscreen`, `pn_set_title`, `pn_destroy`; callbacks for log + window events incl. `Ready`). C# attaches its own mpv client handle (`mpv_create_client`) to the core the native layer owns.
7. **Windows player .NET ↔ native** — same pattern, `Popcorn.Player.Windows.Native/src/lib.rs` (`pn_init` creates the hidden windows and must run on the `pn_run` thread, `pn_mpv_core`, `pn_run`, `pn_quit`, `pn_set_fullscreen`, `pn_set_title`, `pn_window_handle` (dialog owner), `pn_destroy` (terminates mpv while pumping messages: mpv's video window is a child of ours); callbacks for log, window events (`Ready` = WebView2 created) and dropped file paths).

## Build & run

Prereqs: .NET SDK 10 (`global.json`), Node/npm, Rust toolchain + cmake (Popcorn.Linux, Popcorn.Player.Native), libmpv, ffmpeg, libwayland + libEGL + libgbm + libdrm + libxkbcommon (Linux player). Optional for the player's zero-copy video: a libmpv built with the DMA-BUF render API (`make mpv`, needs mpv's own build dependencies). `make` / `build_windows.ps1` run `npm ci` in `Popcorn.Web/` before building (`make npm-ci` to run it alone).

```sh
make mpv                       # init submodule (Tomiscout fork, pinned commit) + build MPV/libmpv.so.2 with the DMA-BUF render API if missing (fetches libplacebo; meson from PATH or a venv in ~/.cache/popcorn)
make update-mpv                # move submodule to latest fork master and rebuild libmpv
make all                       # clean + build both web UIs + Popcorn.Server + Popcorn.Linux (cargo) + Popcorn.Player.Native (cargo) + Popcorn.Player.Linux (server + player `dotnet publish` with ReadyToRun, see below), bundle into Bundle/Linux/ (incl. CEF runtime, stripped libcef.so)
make build-popcorn-player-native  # player native layer only (cargo, same CEF_PATH/CEF version as Popcorn.Linux)
```

Windows: `build_windows.ps1` (needs the .NET 10 SDK, Node/npm, git and Rust (`cargo`, MSVC toolchain) on PATH; stops at the first failure) initializes the MPV submodule and builds `MPV/windows/libmpv-2.dll` if missing, then builds Popcorn.Web (UI + `build:player` overlay) + Popcorn.Server + Popcorn.Windows + Popcorn.Player.Windows (incl. its Rust native layer) into `Bundle/Windows/` (server and app window side by side, player in `Player/` subfolder with libmpv and popcorn_player.dll), plus `Popcorn.Installer.exe` and `release.json`. Player alone: `dotnet build Popcorn.Player.Windows` (after `npm run build:player` in Popcorn.Web), then `Popcorn.Player.Windows\bin\Debug\net10.0\Popcorn.Player.Windows.exe <file>`. Version: `-Version`, default the root `VERSION` file, passed as `-p:Version` to the server/app/player builds. `node set_version.mjs <semver>` (both platforms) writes `VERSION`, the four crates' `Cargo.toml` + own `Cargo.lock` entry and `Popcorn.Web/package(-lock).json`; `Directory.Build.props` makes `VERSION` every .NET assembly's `Version` (`-p:Version` overrides), so `make` builds carry it too. Plugin and plugin-sdk versions are separate. `release_windows.ps1` (optionally `-SkipBuild`) zips the bundle into `Bundle/Release/<ver>/Popcorn-<ver>-windows-x64.zip` (+ the standalone installer), and `-Publish` (`-Draft`/`-Prerelease`/`-NotesFile`/`-Repo`) creates or uploads to the `v<ver>` GitHub release with `gh`. libmpv = the `MPV/src` fork built by `MPV/build_windows.sh` in a portable MSYS2 UCRT64 (`MPV/msys64`, download pinned by checksum, packages from pacman are not pinned; all gitignored) as one DLL with its dependencies linked in statically, including an own FFmpeg (`MPV/build-windows-deps`: every video and subtitle decoder FFmpeg has for Windows, incl. external-library ones built from source there at pinned commits — davs2, uavs3d, xevd, SVT-JPEG-XS, libaribcaption; no image-only decoders (JPEG XL, SVG: thumbnails come from the separate ffmpeg), few encoders/muxers; MSYS2's FFmpeg has no usable static link; bump `DEPS_REVISION` when changing these builds). Meson runs on python.org's signed embeddable Python (`MPV/build-windows-tools`, pinned by checksum). Auto-detected mpv features pick up whatever MSYS2 happens to have installed, so unneeded ones are disabled explicitly (libcurl, libarchive, lua, javascript); only `vulkan-1.dll` stays external (from the GPU driver, no static version), so it does not load on a PC without one. Delete `MPV/windows` and `MPV/build-windows` to rebuild it (`MPV/build-windows-deps` too for FFmpeg). `install_windows.ps1` = `make install-linux` counterpart: stops running instances, copies the bundle to `%LOCALAPPDATA%\Programs\Popcorn`, HKCU Run key for the server, Start menu shortcut to `Popcorn.Windows.exe`, Settings → Apps entry (HKCU `Uninstall\Popcorn`), starts the server. Uninstall runs `uninstall.ps1` (from `Popcorn.Windows/`, copied to the bundle) hidden: stops the processes, removes those entries, the install folder and the data folder (downloaded media stay). ffmpeg/ffprobe are not in the bundle: Popcorn.Installer downloads them into the install folder; `install_windows.ps1` installs need them on PATH. The Windows projects also compile on Linux (`EnableWindowsTargeting`), useful as a build check.

Web bundles (`*/web`, `*/web-player`) and `Popcorn.Server/plugins` are gitignored build artifacts — rebuild the web project after UI changes, the .NET projects only copy whatever is there (as `Content` added in a `BeforeBuild` target, so plain builds and `dotnet publish` both get it; never as `AfterTargets="Build"` copies, publish skips those).

Bundles publish the apps (server, players, Windows app) instead of building them: `dotnet publish -r <rid> --self-contained false -p:PublishReadyToRun=true` (`make`: `DOTNET_RID`, default `linux-x64`/`linux-arm64` from `uname -m`, into `Bundle/Publish/<project>`, same as Windows; `build_windows.ps1`: `win-x64` into `Bundle/Publish/<project>`). ReadyToRun = precompiled native code, no JIT at start-up: matters for `Popcorn.FilenameParser`, whose ~230 regexes are `[GeneratedRegex]` (~145k lines of generated code: ~250 ms of JIT on the first parse without R2R, ~50 ms with; the old `RegexOptions.Compiled` took ~1.4 s). RID-specific output puts native libraries next to the DLLs instead of `runtimes/<rid>/`.

## Runtime data

- Data folder: `DirectoryUtils.DataFolder` = `LocalApplicationData/Popcorn/` (`~/.local/share/Popcorn/` on Linux): SQLite DB, `logs/`, `ThumbnailsCache/`, `StreamCache/`, `downloads/` (download list + torrent engine state; the files themselves go to `DownloadSettings.DownloadFolder`, default `~/Downloads/Popcorn`, one folder per download), `plugins/` (user-installed plugins, win over bundled ones; + `plugins.json` = disabled ids).
- Logging: Serilog everywhere, daily rolling files in `logs/`.
- Desktop entry: `Popcorn.Linux/popcorn.desktop` template (`@INSTALL_DIR@` substituted; Uninstall Popcorn action = `Popcorn.Installer.Linux --uninstall`), installed only if missing by make, (re)written by Popcorn.Installer; launches `Popcorn.Linux`. Window app_id / WM_CLASS is `popcorn` so it matches this file.
- Popcorn.Linux: CEF profile (localStorage, cookies; also the single-instance lock) in `<data>/cef/`, logs in `logs/Popcorn.Linux-YYYYMMDD.txt` + `logs/cef.log`. Env: `POPCORN_SERVER_URL`, `POPCORN_PORT`, `POPCORN_OZONE=x11|wayland`, `POPCORN_NO_SANDBOX=1`.
- Linux player: logs in `logs/Popcorn.Player-YYYYMMDD.txt` (native messages prefixed `[native]`, overlay console `[overlay]`) + `logs/cef-player.log`; throwaway CEF profile per process in `$XDG_RUNTIME_DIR/popcorn-player-cef-<pid>`. Env: `POPCORN_PLAYER_DEVTOOLS_PORT` (chrome://inspect), `POPCORN_NO_SANDBOX=1`, `POPCORN_PLAYER_VIDEO=opengl` (force the EGL video output), `POPCORN_PLAYER_OVERLAY=shm` (force software overlay). F12 opens DevTools, F11 toggles fullscreen. The log says which outputs were picked (`Video: mpv DMA-BUF output ...` / `Video: mpv OpenGL output`, `Overlay: GPU copy ...`).
- Windows player: logs in `logs/Popcorn.Player-YYYYMMDD.txt` too (native messages `[native]`); WebView2 profile in `<data>/webview2-player`. Env: `POPCORN_PLAYER_DEVTOOLS_PORT` (edge://inspect); F12 DevTools, F11 fullscreen.
- systemd: `Popcorn.Server/systemd/popcorn.service` (template, `@INSTALL_DIR@`/`@ENV_FILE@` substituted by make) + `popcorn.env` (copied to `~/.config/popcorn/popcorn.env` only if missing).

## Conventions

- `net10.0`, nullable + implicit usings enabled. Primary constructors common in newer code.
- FFmpeg: everything (FFMpegCore, `FFmpegWrapper`, `FFmpegService`) runs the binaries `Popcorn.Shared/Ffmpeg/FfmpegBinaries.Configure()` picks at start-up (server, both players): ffmpeg + ffprobe in the program's own folder (Windows player: also `..`, the server's), else from PATH. Never add Popcorn to PATH (no env changes, not even for child processes). Linux is meant to bundle them the same way.
- Platform-specific DI via `RuntimeInformation.IsOSPlatform` in `Popcorn.Server/ServiceRegister.cs` and `Popcorn.Player.Core/ServiceRegister.cs`. Native abstractions live in `Popcorn.Domain/Interfaces` (`IPlayerService`, `INativeFolderService`, `INativeFileAssosiation` — note spelling) with Linux/Windows impls in `Popcorn.PlayerServer` / `Popcorn.Shared`.
- Native players: `SettingsModel.Players` is an ordered `PlayerOption` list (built-ins `Popcorn` + `Default`, user-added `Program` = executable gets the file path as its argument, `Script` = shell line with `%args` → quoted path). `PlayerLaunchService.OpenAsync` (used by `FileOpen`) tries enabled entries in order and falls through on failure. `SettingsModel.NormalizePlayers()` (run on load/save) keeps the built-ins present; legacy `UseInternalPlayer` only seeds the initial order.
- Repositories and most services are singletons; `FileStreamService`, `VideoService` scoped.
- DB schema changes: add a new FluentMigrator class in `Popcorn.Persistence/Migrations/` named `<Name>_<yyyyMMdd>.cs`, plus Dapper map updates in `Persistence/Dapper/`. Migrations run on startup only when environment != Development.
- New WebSocket feature: add constant to `SocketRequests.cs` + `socket-requests.ts`, request model under `Popcorn.Server/Models/Requests`, handler method on a `[WebSocketService]` class in `Popcorn.Server/Services`, TS contract under `Popcorn.Web/src/model`.
- The web player (`src/player`) is a lazy chunk (`React.lazy` in `App.tsx`): keep it out of static imports from non-player code (type-only `import type` is fine) so the desktop app never downloads it.
- `Popcorn.Server/plugins` (runtime folder) vs `Popcorn.Server/PluginHost` (code): MSBuild globs are case-insensitive, so the code folder must not be named `Plugins` (the csproj excludes `plugins/**` from compile).
- `Popcorn.Web` path alias `@` → `src/`; `@popcorn/plugin-sdk` → `plugin-sdk/index.d.ts` (type-only imports). Pages in `src/pages/*`, state in `src/state/*` (zustand stores + contexts).
- `Popcorn.Web/post-build.js` also emits `index-chrome.html` / `index-linux.html` (unused leftovers); `post-build-player.js` turns `dist-player/player.html` into `index.html` + `index-chrome.html` (`<base href="http://app.local/">`) and replaces `Popcorn.Player.Linux/web-player`.
- **One player UI, several hosts.** `src/player/PlayerOverlay.tsx` (controls, top bar, progress/thumbnails/intro-outro skip, tracks, episodes, errors) is shared. Components only read the zustand player store and post commands on the local bus (`utils/events`: `play_status_changed`, `set_playback_time`, `skip_seconds`, `volume`, `audio_track_selected`, `subtitle_track_selected`, `folder_open`, `thumb_requested`, `player_close`, ...); they must not talk to the server socket or a `<video>` directly. Hosts: `PopcornPlayer.tsx` (browser: HTML5 video, server WebSocket, floating/PiP) and `native/NativePlayer.tsx` (native players: maps the C# `WebEventHandler` events to the store and forwards commands; transport `native/native-bridge.ts` = `window.wsAddress` WebSocket on both; the Windows player also injects `window.playerHost = 'windows'` (file drops → `chrome.webview.postMessageWithAdditionalObjects('files_dropped')` → paths to C#, host subtitle picker)). Host-specific UI is switched via `player-features.ts` (`floating`, `fileDrop`, `addSubtitle`, `subtitleDelay`) instead of forking components. New overlay command → handle it in both hosts and, for native, in `WebEventHandler.OnMessage` (unknown names throw there).
- `npm run dev:player` serves the overlay from Vite; open `player.html?ws=ws://127.0.0.1:<port>` against a running Linux player (port = Fleck server, usually 8181). When the overlay (re)connects, C# replays the current file's state (`PlayerCore.ResendState`).
- Intro/outro auto-skip: `SegmentAutoSkip` = `Always` / `AfterFirstOccurrence` / `Never` (removed `AfterFirstInItem` still reads as `AfterFirstOccurrence`, numbering kept for stored rows), global in `SettingsModel.SegmentAutoSkip` (Settings page), override per item in `MediaItem.segment_auto_skip` (null = global; player top-bar gear, `Components/PlayerSettings`). `SegmentSkipService` gives the players `PlayerSegments` (locations, modes, `SegmentInfo.seen`). The decision is in the overlay (`ProgressBar.tsx`, `shouldAutoSkip`): made when a segment is entered and only on its first entry per file playback (seeking back shows the button full without a count-down); auto-skip = the skip button's 10 s count-down, or an immediate seek with `SettingsModel.SkipSegmentsWithoutDelay` (`PlayerSegments.SkipSegmentsWithoutDelay`, Settings page). Reaching a segment's end (watched, skipped, seeked past) posts `segment_seen`. Both hosts forward `segment_seen` / `segment_auto_skip_set`: browser to the `SegmentSeen` / `SegmentAutoSkipSet` socket events, native to `WebEventHandler`. `SettingsModel.SkipOutroTail` (default on, `PlayerSegments.SkipOutroTail`): skipping an outro that ends within 10 s of the end of the file seeks to the end.
- Player title and media info: `GetPlayerTitle` (`MediaItemExtensions`) = library item's name without release tags, else the name parsed from the file. Second line of the top bar (`TopBar.tsx`): season / episode, else the full file name; hovering the title always shows the full file name (Mantine `Tooltip`: the Linux player's off-screen CEF does not show `title` attributes). `MediaInfoBuilder` (`Popcorn.Shared/Ffmpeg`) turns the ffprobe analysis into `MediaInfo` rows (settings menu Media info tab, `PlayerSettings.tsx`) and `ChapterInfo`s (`selectCurrentSegmentName`: label between the left and right controls, intro/outro first); delivered in `MediaFileMetadata` (browser) / `TrackLoadedEvent` (native).
- Files still downloading: `downloadRanges` in the player store drives both rules (`player.store.ts`, shared by all hosts). `canSeekTo`: seek bar, skip buttons and arrow keys refuse targets outside the downloaded parts. `needsBuffering`: playback stops 5 s before the end of the downloaded part it is in (or at once outside any) and goes on at 10 s ahead or when that part reaches the end of the file; `PlayerOverlay` keeps `isBuffering` up to date and shows the "Buffering" spinner, the hosts hold the video on its changes (native: `play_status_changed`, so `isPlaying` stays the user's wish).
- Next episode: end of file and the next button ask for a `NextFilePlan` (`GetNextFilePlan` in `MediaItemExtensions`; browser socket `PlayerNextFile`, native `next_file_plan`), applied by `player/next-file.ts`: play it, or open `NextFileDialog` when season/episode numbers have a hole (not for season 0), or, when the file played to its end and nothing is next, show `FinOverlay` (`src/player/fin.png`, imported because the player build has no `public/`). The previous button plays `NextFilePlan.PreviousFileId` from the metadata (`play_file`). Refresh files = `PlayerRefreshFiles` / `next_file_refresh` (rescan, new plan: plays the episode if it is now there). Find file = `/watch/<item>?tab=sources&q=<title> <SxxExx>`: browser floats the player and navigates, native `open_app_path` → `AppWindowLauncher` → `Popcorn.Linux --open-path=<path>` (a running instance takes it over in `on_already_running_app_relaunch`; no desktop app: default browser).

## Known issues / gotchas

- **Windows is untested**: the server (`WindowsPlayerService`, `WindowsFolderService` with pickers via STA PowerShell WinForms dialogs, `WindowsFileAssociation`, `WindowsProcessRunner`, tray), `Popcorn.Windows` and the install script build but have not been run on Windows.
- **Windows Smart App Control** blocks freshly compiled unsigned programs, so meson's sanity check fails on a native build (`WinError 4551`). `MPV/windows.cross` declares the build as a cross build, so nothing it compiles gets run; never `ldd` the DLLs there either (`MPV/build_windows.sh` reads import tables with objdump). It also blocks MSYS2's own unsigned binaries at random (Python `.pyd` modules, `bsdtar`, even `ls` after updates; Event Viewer → `Microsoft-Windows-CodeIntegrity/Operational`, event 3077), hence the signed Python for meson and `System32\tar.exe`. The built libmpv itself does load with it on.
- Windows player overlay: WebView2's SmartScreen check (`IsReputationCheckingRequired`, on by default) holds every `http://app.local` page ~2 s before parsing it; `overlay.rs` turns it off. Measure overlay start-up with `POPCORN_PLAYER_DEVTOOLS_PORT` + `performance.getEntriesByType('navigation')` (`domInteractive`).
- `Popcorn.Player.Windows` needs `cargo` on Windows (its build compiles Popcorn.Player.Windows.Native); on Linux it only compiles the C# part.
- **Linux player: CEF inside a .NET process.** Chromium's start-up resets SIGCHLD/SIGSEGV/SIGTERM/... to SIG_DFL; `cef_app.rs` (`signals`) snapshots and restores .NET's handlers. Child processes started before that would never be reaped (`Process.WaitForExit` hangs), so the C# side starts loading (FFProbe) and the server link only on `PlayerNative.Ready`, which also waits for the mpv render context (vo=libmpv refuses files opened before it exists).
- Linux player CEF disables `LocalNetworkAccessChecks*`: otherwise Chromium cancels the overlay's WebSocket to 127.0.0.1 after connecting.
- Linux player CEF disables `WaylandFractionalScaleV1` (hack, see comment in `cef_app.rs`): with it on, OSR ignores the device scale at fractional scales (1.5) -> page at dpr 1, DIP-sized frames upscaled by the compositor -> blurry overlay. `--force-device-scale-factor` does not help. Recheck after CEF updates: overlay `devicePixelRatio` must equal the window scale.
- `index-linux.html` (app.local:// base for WebKit) is no longer used by any player.
- **Player DMA-BUF video needs a patched libmpv**: `MPV_RENDER_API_TYPE_DMABUF` (`include/mpv/render_dmabuf.h`, `video/out/vulkan/libmpv_dmabuf.c`, client API 2.7) lives in the mpv fork (`MPV/src` submodule, written as an upstream-style render backend next to OpenGL/D3D11). `make mpv` builds it: meson + libplacebo >= 7.387 as `subprojects/libplacebo` (system one is older; commit pinned in the makefile), `-Dwayland=disabled` (not needed for libmpv). Stock libmpv returns MPV_ERROR_NOT_IMPLEMENTED and the player uses OpenGL.
- NVIDIA GBM cannot allocate XRGB2101010; the video buffer negotiation (mpv formats ∩ compositor feedback, mpv's 10-bit-first order) ends up on ARGB2101010 there. The video plane stays opaque (mpv writes alpha 1, opaque region set).
- mpv's vo_gpu renderer (used by every libmpv render backend) dereferences missing textures when Vulkan allocations fail (e.g. VRAM nearly full while a game runs: libplacebo `VK_ERROR_OUT_OF_DEVICE_MEMORY` -> segfault in `gl_sc_uniform_texture`). Same with stock `--vf=gpu=api=vulkan`; not specific to the DMA-BUF backend.
- `Popcorn.Domain.csproj` (Dapper) and `Popcorn.Application.csproj` (Serilog) contain stale `<Reference HintPath="..\..\..\.nuget\...">` entries; they produce MSB3245 warnings and should be replaced by PackageReferences.
- `WindowsPlayerService.GetPlayerExePath` dev fallback walks up to a directory literally named `Popcorn` — depends on repo checkout folder name.
- `Directory.Build.targets` pins net10.0 targeting/apphost packs to 10.0.0 and uses the portable `linux-x64` apphost: distro SDKs (Arch) otherwise fail restore with `NU1101 Microsoft.NETCore.App.Host.arch-x64` whenever the SDK patch and `dotnet-targeting-pack` patch differ. Runtime requirement stays 10.0.0 + roll-forward.
- Build emits ~200 nullable warnings; not treated as errors.
- `Docs/NOTES.md` holds a personal TODO list and a SQL snippet for migrating a Windows DB to Linux paths.
